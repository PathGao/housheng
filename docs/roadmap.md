# 家庭版进度与后续需求

2026-10-03：已完成以下家庭版实现，真机验收结果以 [验证记录](device-validation.md) 为准。

## 当前实现

1. **通知管理**：显式选择名单内来源，按关键词处理，支持来源始终放行和系统通知设置入口。通知执行选择持久化，授权与服务连接分别显示；暂停会保存为停止执行。页面自动翻页仍是临时验证功能。
2. **家庭报告**：保存最近30个自然日的来源汇总，可预览最近7天或30天，展示收到次数、命中、清理请求、受保护次数、当前规则及有限连接记录。可主动复制或系统分享，也可清空本机历史。
3. **应用清单**：主动查询当前可见、有桌面入口的应用，标记近30天首次安装，支持预览分享和进入系统详情。家庭报告可选附上清单，默认不查询。近期安装不等于有害。

报告不含通知标题、正文、验证码或私聊。通知更新计入收到次数，清理请求不等于已删除。覆盖仅限选择来源且服务连接期间，不把没有记录说成全手机没有通知。口径详见 [应用范围](app-scope.md)。

## 下一阶段

前期主线是快速、可靠的信息流筛选：先完成真实页面适配、判断与执行，以及误筛后的放行调整。下述后期解说能力不作为前期交付的依赖，不让长文本生成阻塞日常浏览。

1. **日常稳定性**：验证24–72小时使用、锁屏过夜、省电、内存回收、清理最近任务和重启后的连接与恢复行为。功能测试通过不能替代这项验收。
2. **真实信息流适配**：先确认普通信息流区域，再读取和分类。Laya已用于调试版USB验证场管线，真实应用页面仍暂不读取；当前仅有验证场的本次进程统计，不能生成真实话题比例。后续Clef适配沿用[固定决策协议](../validation/laya/README.md)，尚未接入其API。
3. **家庭协作演进**：当前由孩子阅读报告、指导父母在本机调整。孩子端、远程同步和远程调整未实现，待实际使用反馈后决定。后台新增/移除事件、安装来源和长期信息流分类汇总也未实现。

## 后期：大语言模型辅助解说与建议

2026-10-03记录，尚未实现。信息流筛选稳定后，再引入大语言模型，帮助父母理解内容中的问题及可采取的做法。对有问题的信息，支持保留观看并配合解说，不把所有问题内容都直接屏蔽；是否继续观看由父母选择。

1. **说明问题**：用易懂的语言解释具体哪句话或哪种表达值得警惕，例如夸大效果、隐瞒条件、制造恐惧或诱导转发。区分事实错误、缺乏证据与单纯不符合个人偏好，不把模型判断写成定论。
2. **补充依据与背景**：结合必要的信息核验，说明原内容遗漏了什么、哪些说法有可靠依据，提供可追溯来源。无法核实时明确表示不确定，不能仅凭大语言模型生成一段看似合理的反驳。
3. **给出行动建议**：在解释之后提供有依据、适合当前情境的建议，让父母知道可以怎么核实、如何避免被误导、是否需要向孩子或专业人士求助。建议应尊重父母的选择，不以训斥或强制替代判断。

例如，遇到夸大功效的内容，可以让父母继续看，同时指出绝对化承诺和证据缺口，补充核验途径与下一步建议。具体展示方式（伴随提示、展开解说等）留待后期验证，本阶段不承诺悬浮覆盖、语音讲解或自动事实核验已可用。

快速筛选与较慢的解说分开处理：先完成浏览所需的及时判断，解说按需加载或异步呈现，不能等大语言模型生成完才允许继续浏览。该能力继续遵守应用名单、页面隐私和不跳过广告的既有边界。

## 固定边界

后生不做李跳跳或AdBlock类广告屏蔽，不点击跳过广告，不绕过应用限制。只使用用户已有的应用内/系统权限和普通内容信息流控制能力，广告与无法确认类型的页面不自动操作。

内容应用名单与安装清单分别授权。浏览器可出现在应用安装元数据中，网页、地址、搜索、历史和通知不采集。报告始终由父母预览后主动分享，不自动发送给孩子。
