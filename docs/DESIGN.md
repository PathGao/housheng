# 后生设计文档

## 一、术语表

文案规则：

1. 写事实，不写情绪和口号。不用“帮爸妈看一眼”“照看”这类话。
2. 称呼用“你”。对象用“家人”，不写死“孩子”“爸妈”。
3. 行标题用名词，按钮用动词。避免“管理、设置、更改”这类泛动词做标题。
4. 一句话说一件事，说明最多一句。不写“不代表”“仅供”等防御性句子，必要的边界写进“后生会做什么”页。
5. 数字用阿拉伯数字加单位，数字与单位之间空格：“3 个应用”“7 天”。
6. 标签、按钮、状态词不加句号。说明句加句号。

服务状态只用这几个词，标签与 `ServiceStatus` 一一对应。图标、颜色、标题和首页按钮见 [服务状态](#服务状态)。

| 概念 | 用 | 不用 | 为什么 |
|---|---|---|---|
| 未授权 | 未授权 | — | — |
| 已授权未连接 | 已断开 | — | — |
| 观察 | 只记录 | — | — |
| 执行 | 清理中 | — | — |

## 二、产品决策

2026-10-03，家庭版首页、通知清理、家庭报告、应用清单、设置与诊断已实现，同日按 [视觉设计](#三视觉设计) 重写界面，家庭版真机验收见 [验证记录](device-validation.md)。随后已接入调试版 Clef API 模型管线和真实应用实验筛选，范围见 [应用范围](app-scope.md)，现状见 [当前限制](development.md#当前限制)。

### 页面分工

- 首页：通知状态面板与最近 7 天次数，通知清理、家庭报告、应用清单入口，清理中才显示暂停，另有设置与诊断和“后生会做什么”。显示日常来源选择数量，服务状态通过事件通知与返回页面时刷新，没有轮询。没有无障碍授权弹窗，没有模拟 AI 统计。
- 通知清理：按需进入系统授权，分别显示尚未授权、已授权未连接、观察和执行。用户可以选择来源、按应用始终放行、保存关键词、打开对应系统通知设置。通知执行意愿保存在本机，连接中断不清除选择，首页暂停会保存关闭状态。观察期间仍处理所选来源的回调并记录统计，暂停自动处理不等于关闭观察。
- 家庭报告：可选最近 7 天或 30 天，先预览再复制或系统分享。显示来源次数、命中、清理请求、受保护次数、当前规则与独立的始终放行名单，以及有限连接记录。用户主动勾选后才读取完整可见应用清单并标记近 30 天安装。生成失败可重试，清空历史前二次确认，清空与服务写入经过同一队列。没有自动发送或远程修改父母手机的能力。
- 应用清单：主动查询，后台执行 PackageManager 读取，显示加载与失败提示。近 30 天按系统首次安装时间计算。选中应用后说明并打开系统详情，后生不自动卸载。清单只在页面内存保留，旋转可恢复，进程退出后不保存。
- 设置与诊断：原有验证场、来源配置、截图及有限诊断记录保留在独立页面。仅供家人协助和工程验证，不成为首页日常流程。

### 数据与功能边界

报告中的通知次数包含更新，只覆盖已选择来源且服务收到的回调，不等同于手机全部通知或独立消息数。清理请求不冒充成功拦截，也无法撤回已经发出的声音和横幅。默认报告排除验证场通知，通知标题、正文和原始通知标识不写入数据库。安装清单最多 500 个当前可见、有桌面入口的应用，不是完整安装历史。

真实应用实验筛选的读取范围与遮挡方式见 [应用范围](app-scope.md)。自动翻页与截图继续限定在独立验证场。应用清单不授予内容读取权，不读取浏览器、私信或账号页面，不自动跳过广告。家庭协作通过用户预览后复制或系统分享，在父母手机上修改设置；不提供账号同步、服务器或远程控制。

### 依据与取舍

已阅读用户指定的 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 技能，运行 `senior mobile companion accessible calm --design-system`。其适老高对比建议适用，但营销落地页结构、网页字体和转化按钮不适用。进一步以 `senior accessible mobile utility --domain product` 核实命中 Senior Care/Elderly，采用大字、暖中性色、简明导航。项目使用 Android 原生 Views，技能没有该栈专属指引，不套用 Compose 或 Web 实现。

颜色、字号、尺寸、状态词表和文案规则以 [术语表](#一术语表) 和 [视觉设计](#三视觉设计) 为准，颜色集中在 colors.xml，组件集中在 ProductUi.kt。图标为 Material Symbols Rounded 转成的 VectorDrawable，由 scripts/material-icon.sh 生成，不引入图标或动画依赖。

本版固定浅色主题，并关闭系统强制反色。未实现独立深色主题，不能宣称已验证深色适配。页面按系统栏与刘海 Insets 留白，长内容纵向滚动，行只设最小高度。应用列表由原生 ListView 回收行，避免一次创建 500 个控件。

## 三、视觉设计

2026-10-03 确认并实现。组件在 `ProductUi.kt`，颜色在 `colors.xml`。页面分工见 [产品决策](#页面分工)。设计稿与实机截图在本部分末尾。

### 依据

| 来源 | 采用 | 不采用 |
|---|---|---|
| Material 3、Android 无障碍指南 | 颜色角色、sp 字号、48dp 触控下限、列表行结构、按钮层级、开关即时生效 | 默认 14–16sp 正文（对父母偏小） |
| Apple HIG | 分组列表 + 分区脚注放说明、行尾 › 表示可进入、弹窗写法、权限在用到时才要 | iOS 控件外观 |
| 工信部《APP 适老化通用设计规范》 | 主要文字 ≥18、主要控件 ≥60dp、行距 ≥1.3、对比度 ≥4.5:1、颜色不单独传意、弹窗关闭易点 | — |
| UI UX Pro Max（Senior Care） | 大字、平静配色、状态不只靠颜色 | 网页字体、落地页结构、转化按钮 |

### 设计原则

1. 用户以为自己在用系统设置。版式跟 Android 设置页一致：分组列表、整行可点、行尾箭头或开关。
2. 每屏先回答“现在怎样”，再给“能做什么”。状态在最上，操作在下。
3. 一种信息只用一种样式。状态、数值、操作、说明各有固定外观，见下表。
4. 说明放在分组下方，一组最多一句。隐私和边界说明集中在“后生会做什么”页，不在每页重复。
5. 一屏最多一个实心主按钮。破坏性操作单独成组放页底，二次确认。

### 信息类型与样式

| 类型 | 样式 | 示例 | 禁止 |
|---|---|---|---|
| 页面标题 | 顶栏 title 22 | 通知清理 | 口号、副标题 |
| 状态 | 状态标签（图标 + 词 + 底色）+ 一句 title | 清理中 / 正在按规则清理通知 | 只用颜色，用正文段落描述状态 |
| 数值 | number 30 + support 标签 | 128 · 7 天收到 | 把数字写进句子里，把清理请求写成“已清理” |
| 分区 | section 16 主色 | 管理的应用 | 用卡片标题代替 |
| 设置项 | 行：label 18 + support 16 + 开关 | 按规则清理通知 / 关闭时只记录次数 | 开关加“保存”按钮 |
| 导航 | 行：label 18 + 当前值 + › | 应用清单 · 新装 2 个 | 用大按钮做页面入口 |
| 操作 | 按钮，动词开头，≤6 字 | 分享给家人 | “返回首页”按钮（用顶栏 ←） |
| 说明 | support 16 次色，分组下方一句 | 电话、短信、闹钟始终保留。 | 多段免责声明 |
| 反馈 | 状态原位更新；复制等瞬时结果可用 Toast | 已复制 | 用 Toast 传达重要状态 |

### 服务状态

状态标签见 [术语表](#一术语表)。

| 标签 | 图标 | 颜色 | 标题 | 首页按钮 |
|---|---|---|---|---|
| 未授权 | error | warning | 还不能清理通知 | 去系统设置允许 |
| 已断开 | link_off | error | 通知服务已断开 | 重新连接 |
| 只记录 | visibility | neutral | 只记录，不清理 | 无 |
| 清理中 | check_circle | ok | 正在按规则清理通知 | 暂停自动清理（描边） |

| background | #F2F4F3 | 页面底 | — |
| surface | #FFFFFF | 分组、面板 | — |
| text | #1B2622 | 正文 | 15.6:1 |
| text-secondary | #56635F | 说明、数值标签 | 6.3:1 |

### 文字

系统字体（中文 Noto Sans CJK / 厂商字体），不内置字体。字号用 sp，随系统字号放大。行距 1.3–1.5。

| 层级 | 字号 / 字重 | 用途 |
|---|---|---|
| headline | 28 / Bold | 首页“后生” |
| title | 22 / Bold | 顶栏标题、状态标题 |
| number | 30 / Bold，等宽数字 | 统计数值 |
| label | 18 / Medium | 行标题、按钮 |
| body | 18 / Regular | 对话框正文、报告全文 |
| section | 16 / Medium，主色 | 分区标题 |
| support | 16 / Regular，次色 | 行副文本、分组说明 |

不出现小于 16sp 的文字。

### 尺寸

4dp 网格。页面左右 16dp，屏宽 600dp 以上至少 48dp，内容最宽 840dp，底部操作栏同样对齐。分组之间 16dp，分区标题上 20dp 下 8dp。

| 元素 | 规格 |
|---|---|
| 按钮、分段选择 | 高 ≥60dp，全圆角 |
| 列表行 | 最小高 64dp，左右 16dp，元素间距 16dp；不写死高度 |
| 行首图标 | 40dp 方块，圆角 12dp，内图标 24dp |
| 开关 | 52×32dp，整行可点 |
| 顶栏 | 64dp，← 返回 48dp 触控区，内容描述“返回” |
| 圆角 | 分组与面板 16dp，状态标签 8dp |
| 底部操作栏 | 白底，上分隔线，放本页主操作 |

### 组件

1. 按钮层级：实心 > tonal > 描边 > 文字。实心每屏最多 1 个。破坏性用红色文字按钮，单独成组放页底。
2. 分段选择：用于 7 天 / 30 天这种二选一，选项文字尽量短。选中项加 ✓，不只靠底色。
3. 开关：拨动即生效，不配保存按钮。关闭的行文字变灰，副文本写明“未管理”。
4. 对话框：只用于授权说明和破坏性确认。标题写发生什么，按钮写动作（“清空记录”/“保留”），不用“确定/是/否”。取消在左，确认在右。
5. 空状态：一句说明 + 一个能做的事。示例：“还没有记录。选好应用后开始统计。”
6. 图标：Material Symbols Rounded，用 `scripts/material-icon.sh` 导出为 VectorDrawable，不加依赖。图标不单独表意，旁边必须有文字。按钮不带图标。
7. 大字号：系统字号超过 130% 时，行内的值移到标签下方，数值区和底部操作栏按钮改为上下排列，避免标签按字断行。

### 验收

1. 系统字号最大档下所有页面不截断、不重叠。
2. TalkBack 能读出状态标签全文、开关名称与开关状态、返回按钮。
3. 每屏实心按钮不超过 1 个。
4. 颜色关掉（灰度截图）后状态仍可分辨。

### 交付检查

代码检查已确认：文字可换行、原生按钮、文字状态、来源边界、系统栏留白、ListView 回收、无自动请求权限、无装饰动画。仍需检查辅助说明的 16sp 是否符合父母实际阅读需求。实际小屏、横屏、大字号、TalkBack、键盘与不同系统版本需设备验证，不能用代码检查代替。

家庭版已验证报告复制及系统分享请求，未代替用户向真实联系人发送。24–72 小时后台、锁屏、省电、自然回收及重启稳定性仍待验证，不能由短测推断。具体构建、测试数量和设备以最新验证记录为准。
