# 后生

[![构建与检查](https://github.com/PathGao/housheng/actions/workflows/ci.yml/badge.svg)](https://github.com/PathGao/housheng/actions/workflows/ci.yml)

帮爸妈看一眼。

给父母使用的中文 Android 手机助手，帮助家人管理通知、了解信息来源，逐步实现快速的信息流筛选。当前为家庭试用版。

## 项目状态

2026-10-03：v0.2.0-family-preview 已实现通知管理、家庭报告和应用清单。调试版新增Laya本机模型验证链路，经USB处理合成验证场文字，并通过原有守卫执行下滑。真实应用的信息流适配尚未接入，通知仍使用本地关键词。长期后台稳定性仍待日常使用验证。构建、准确率、时延与真机证据见[模型验证](docs/laya-validation.md)和[家庭版验证](docs/device-validation.md)。

## 现有能力

- **通知**：显式选择来源，默认观察。开启执行后，请求清理命中关键词且可清除的普通通知，也可将来源设为始终放行。消息、电话、闹钟、常驻等受保护通知保留。系统已发出的声音和横幅不保证被阻止。
- **家庭报告**：按来源保存最近30个自然日的通知汇总，预览最近7天或30天的次数、清理请求、当前规则和连接记录，再主动复制或通过系统分享。可选择附上当前应用清单；默认不查询。孩子指导父母在本机调整，没有账号、远程控制或自动同步。
- **服务状态**：区分尚未授权、已授权但断连、观察和执行。通知处理选择会保存，服务连接恢复后按原选择工作；暂停会保存为停止执行。页面翻页仍是验证场的临时开关，进程重启恢复观察。
- **范围**：首批内容名单为抖音、快手、小红书及所列极速版。浏览器、聊天类和名单外应用不采集。名单内也必须先确认是信息流页面，当前真实应用页面均待适配，暂不读取。
- **安装清单**：主动查询当前可见、有桌面入口的应用名称、包名及首次安装时间，标记近30天安装，可预览复制/分享给孩子，并转到系统详情由家人决定卸载。不会据此授予内容访问权，也不自动认定为垃圾应用。
- **内容统计**：本次进程中确认的普通内容展示次数与分类计数，验证场独立统计。模型未接入时记为未分类，真实应用未适配时不采集，不生成虚构比例。
- **受控动作**：独立“后生验证场”提供普通内容、广告和未知页面。仅已确认的普通内容可翻页，检查来源、页面代次、开关及500ms期限，一条内容最多执行一次。
- **截图**：用户显式预约，5秒后对已勾选验证场截屏一次。真实应用截图暂未开放。整屏可能含状态栏信息，仅保存最近一张于私有缓存，可预览、删除，不上传。

release构建不请求网络权限。调试版允许经USB访问本机模型，默认关闭，仅作用于验证场，不包含云模型、OCR、音频采集、Root或Shizuku。通知管理、家庭报告和应用清单不依赖无障碍权限。通知标题和正文不持久化，诊断内存日志限50条；最近验证场页面文本最多4000字。家庭报告可清空历史汇总与连接记录，不修改权限和规则，已分享的副本不会被撤回。

## 产品边界

不做李跳跳或AdBlock类功能，不屏蔽广告、不自动跳过广告、不点击“跳过广告”、不绕过应用限制。只使用用户已有的应用内/系统权限控制能力，并筛选普通内容信息流。广告和无法确认类型的页面不自动操作。

这是一项产品范围约定，不是法律合规结论。

## 构建和验证

最低Android11（API30），编译SDK35，JDK17。Gradle使用仓库wrapper，Android插件8.9.2，Kotlin2.1.20。标准环境配置 `JAVA_HOME` 和 `ANDROID_HOME` 后运行：

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :fixture:assembleDebug :app:lintDebug :fixture:lintDebug
```

本机工具链位于忽略的 `.tools/`，使用 `scripts/build-local.sh` 替代 `./gradlew`，缓存留在项目中。其他机器无需复制此目录，使用自身JDK和Android SDK即可。

主程序：`app/build/outputs/apk/debug/app-debug.apk`。独立验证场：`fixture/build/outputs/apk/debug/fixture-debug.apk`。二者为调试签名，供家庭开发验证，不是公开发布包。

日常试用从“管理通知”按需授予通知使用权、选择来源，先保持观察。验证场的无障碍翻页和截图入口在“设置与诊断”，无需为日常通知管理授权无障碍。测试操作及实际验证结果见 [真机验证](docs/device-validation.md)。

## 持续集成

每次推送和拉取请求都会执行 Android 单元测试、Lint、调试包与发行包构建，并检查发行包没有网络权限。模型协议和指标测试仅用 Python 标准库，不下载模型、不使用 API 密钥。CI 只编译设备测试，不代替小米真机验收或长期后台稳定性验证。

在 [构建与检查](https://github.com/PathGao/housheng/actions/workflows/ci.yml) 中打开成功的运行，下载 `housheng-debug-apks` 可获得主程序与独立验证场安装包，保留 14 天。覆盖安装要求签名相同；已安装本机调试版的手机继续使用原工具链构建，避免因 CI 的临时签名不同而无法更新。

## 实现入口

`DecisionPolicy.kt` 包含分类器接口与纯Kotlin动作守卫。模型后续只替换分类器，来源、内容类型、时限和执行检查仍由本地代码负责。

`MainActivity.kt` 是家庭版首页，`NotificationsActivity.kt` 管理来源与规则，`ServiceHealth.kt` 区分授权和连接状态。`ReportStore.kt` 保存汇总，`ReportActivity.kt` 提供报告预览和主动分享。

`NotificationService.kt` 处理通知。`FeedService.kt` 处理验证场页面、滚动及截图。`DiagnosticsActivity.kt` 保留验证与诊断入口，`fixture/` 提供独立合成测试应用。

应用名单、统计口径和隐私边界见 [应用范围](docs/app-scope.md)，后续工作见 [需求记录](docs/roadmap.md)。安装清单仍是主动查询，不记录后台安装历史；真实信息流分类和远程调整尚未实现。
