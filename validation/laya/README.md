# Laya 本地技术验证

2026-10-03开始。先测Mac上的中文决策质量和延迟，随后按用户要求把验收重点改为手机功能管线：验证场文字经USB送到Mac，返回决策，在显式执行模式下验证真实无障碍下滑。不采集真实通知或真实应用页面。

## 验收预期

- T1 安装并运行真实多语言权重，记录代码/权重版本、依赖和硬件。
- T2 冻结合成中文数据与判断规则后运行，报告准确率、混淆矩阵、保留内容误过滤率及置信度，不能以接口成功代替质量。
- T3 单条短文本完整判断P95不超过500ms，区分冷启动与预热后推理。包含分词与结果解析，GPU计时同步。
- T4 开发集只用于检查接线，评估集不用于调整提示词。若试验失败，保留失败并说明改判需要什么证据。
- T5 按用户后续要求，准确率只记录，不作为本轮管线验收门槛。默认观察；仅在合成验证场显式启用执行，验证模型判定能触发真实下滑，广告/未知页、切页旧结果、超时、断连和异常响应不能触发操作。

最初准确率门槛为至少90%、非过滤样本误过滤为0，实测未达到。用户明确本轮先确认管线、后续换Clef，因此保留原始结果，不调整样本或以准确率阻塞管线。小规模合成测试不代表真实产品已验收；不把未校准概率当作正确率。

模型、虚拟环境、缓存和原始运行记录放在项目忽略的`.tools/`内。源码固定为Laya提交`fa9a2a7070b1789912a49ae24603bbfb1a78b001`，多语言权重固定为上游列出的`e4e9ddf21a7b1903b7acffd8814ad4307bf63a67`。没有API额度或订阅。

## 运行

在仓库根目录执行。需要Git和uv。依赖安装到项目`.tools/`，模型首次下载需要网络。

```sh
validation/laya/setup.sh
```

离线跑固定评估，输出文件必须是新路径，避免覆盖证据：

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 validation/laya/python.sh validation/laya/evaluate.py --split eval --repeats 3 --output .tools/laya-results/new-eval.json
```

启动本机桥接服务。保持此终端运行，服务仅监听127.0.0.1:18765，加载与推理离线，正文不写日志。

```sh
validation/laya/python.sh validation/laya/bridge.py
```

另一终端连接USB并解锁手机，再运行包含原有回归和模型管线的真机检查：

```sh
scripts/test-device.sh --model
```

手动验证：后生 → 设置与诊断 → 勾选验证场页面 → 开启“验证场使用本机模型”。保持“执行内容翻页”关闭时只记录模型结果。要验证下滑，显式开启翻页，然后打开验证场的“模型下滑验证”。测试卡片仅第一条可自动操作，第二条作为完成页不继续推理。退出验证后关闭两个开关。

## 后端替换契约

手机仅在调试版包含网络能力，release包没有INTERNET权限。请求只发到固定回环地址，经`adb reverse tcp:18765 tcp:18765`到Mac。当前只有已勾选、具有普通内容标记的验证场页能触发请求。

`POST /v1/classify`请求：

```json
{"request_id":"uuid","source":"io.github.pathgao.housheng.fixture","text":"合成文字"}
```

响应：

```json
{"request_id":"同一个uuid","decision":"filter","model":"laya-multilingual","elapsed_ms":32.0}
```

`decision`只接受`keep`、`filter`、`uncertain`。`filter`进入既有动作守卫，`keep`和`uncertain`保留。非200、错请求ID、畸形JSON、超过4KiB响应或过期结果均保留，不重试、不降级为关键词执行。手机不接收模型指定的坐标或手势。

后续Clef适配只需替换桥接服务的推理函数并归一化为上述协议，API密钥留在服务端。尚未实现或测试Clef调用、国内网络时延、脱离USB的部署和真实应用页面适配。

已在当前项目环境完成安装、离线推理和真机验证。`setup.sh`通过Shell语法检查，尚未在第二台干净机器完整重装验证。
